## 原始需求

用户验收反馈（2026-11-19）："站在用户的角度，你考虑得太不完善了，连读直接嵌在对话框就行了，为什么还要去单独的卡片，单个词也是在对话框里面才会点，而且点了单个词学习发音后为什么会跳转到另一个卡片，还不能回退，从用户最可能的使用习惯出发去设计好吗"。

## 需求分析

- **痛点**：TASK-0029/0031 的学习动作都跳模态大卡（连读卡/规则卡浮层），打断当前对话语境、无法回退——违背"原地学习"的使用习惯。
- **目标**：①点单词 → **贴词小气泡**（原地弹出：🔊 听发音 + 规则一句话 + 例词 IPA + 「完整讲解+跟读→」），点空白关闭，无导航无回退问题；②连读 → **词卡/例句内嵌手风琴展开**（整句🔊 + 连读位置提示 + 联诵/连音速览），不再弹独立卡；③模态大卡只保留两个入口：读音小册子浏览、气泡里主动点「完整讲解」的深层学习（跟读/进度在那里）。
- **改动点**（引用项目地图 `docs/project_content.md`）：
  - `frontend/app.js`（openWordPopover/closePronPopover/openFullFromPop；toggleLinkingInline 取代 openLinkingCard 模态；token/入口改指向）
  - `frontend/styles.css`（气泡 + 内嵌块样式）
  - `frontend/index.html`（js v16→v17、css v14→v15）
- **涉及数据**：无数据/端点/数据库改动

## 方案（持续迭代模式，按用户验收反馈直接实施）

- **两层设计**：浅层 = 原地（气泡/内嵌），深层 = 模态（小册子/完整讲解+跟读）；浅层入口零导航。
- **气泡定位**：贴 token 下沿，视口内钳制（放不下翻到上方），body 直挂、document capture 外点关闭。
- **内嵌连读**：复用 detectLinkingPairs 与规则速览，块插在触发按钮所在行之后，按钮文案切换「🔗 连读 ↔ 🔗 收起连读」。
- **风险**：气泡在窄屏可能贴边（已钳制）；词卡滚动容器内定位用页面绝对坐标（scrollX/Y），滚动时气泡不跟随（关闭重开即可，可接受）。
