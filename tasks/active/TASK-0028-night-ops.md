## 原始需求

"zcode 晚上 23:00-9:00 有耐用的 GLM-5.3-Flash，我想尽量消耗，自动对我的项目进行开发迭代，有 bug 自己修，强制禁止提问和早停，有错先分析，禁止机械重试，父子 agent 分工，只在这个时间段使用这个模型。项目内的各个子项目都需要。"

用户拍板（2026-11-19）：
1. 白名单 = **项目文档**：各子项目 README/docs/TASK 文件中已写明的设计目标方向即可夜间实施；文档未覆盖的新方向夜间只出提案。
2. git：**每完成一个大的变更或完成一个功能就提交**（绿测前提），不 push，晨起用户审夜报后自行推送。

## 需求分析

- **目标**：每晚 23:00 由 Cron 自动化启动"夜班总指挥"（父 agent），巡库生成任务池，逐任务派子 agent（侦察/实现/测试）实施，绿测即 git 提交，09:00 强制收口写夜报；全程零人工交互。
- **改动点**（引用项目地图 `docs/project_content.md`）：
  - docs/ 新增章程 `docs/night_ops.md`
  - tasks/ 新增任务池 `tasks/night_backlog.md` 与夜报目录 `tasks/night_reports/`
  - 两张地图各加 1 行索引
  - ZCode Cron 自动化 ×2（23:00 夜班 / 09:00 晨报，不入仓库，属于工作区自动化）
- **涉及数据**（引用数据地图 `docs/data_content.md`）：
  - `tasks/night_backlog.md`、`tasks/night_reports/*.md` 均入 git，生产者/消费者为夜班 agent 与用户

## 方案（已确认）

- **实现思路**：ZCode CronCreate（时钟精确、可 recurring、跨重启持久）作触发层；OffPeakCreate 仅作白天手动补充（无保证开始时间、不能自我续链，不满足准点开跑）。父 agent（总指挥）单会话跑整晚（依赖上下文自动压缩），子 agent 按角色分工；错误协议 = 先分析→假设清单→每假设一次验证→3 假设失败标 blocked 换任务（整体不早停，循环领任务到 09:00）；项目文档即白名单 + 硬性红线（credentials/GLM 计费/真机爬虫/data 目录/force push）；任务文件、看板、归档全流程照常走 AGENTS.md 工作流，夜间"方案确认"环节由章程代行。
- **改动点清单**：
  - 新增：docs/night_ops.md、tasks/night_backlog.md、tasks/night_reports/.gitkeep
  - 修改：docs/project_content.md、docs/data_content.md（各 1 行索引）、tasks/task_state.md（本任务登记）
  - 创建：Cron「每晚23:00夜班自动迭代」+「每天09:00夜班晨报」
- **风险与限制**：电脑整夜不睡眠 + ZCode Desktop 运行是硬前提；git 不在 system shell PATH（章程第 0 步环境预检拦截，预检失败写夜报上报）；整晚单会话依赖上下文自动压缩（跑两晚评估，不稳改波次制）；cmd 中文乱码 → 章程要求一律用 Read/Write 工具处理文件。
- **用户确认日期**：2026-11-19
