用户要求："这些自检程序做成一个一键启动脚本"——把验收前手工执行的启动前自检（key/依赖/解释器/端口）+ 拉起双服务（后端 8000 / ASR 8010）+ 健康检查固化为一键脚本。

## 需求分析

- **目标**：双击一个脚本即完成「自检 → 启动 → 健康检查 → 打开验收入口」，替代每次手工逐条执行。

  - 不涉及数据文件变更；脚本只读 `data/input/texts.json` 存在性

## 方案（已确认）

- **实现思路**：单个 `start.bat`（与 `asr_service/start_asr.bat` 同风格，chcp 65001、零新依赖）：
  1. 自检：后端解释器（`YAYA_PYTHON` 覆盖 → WorkBuddy 3.13（实测含 fastapi/uvicorn）→ 系统 Python → 缺则指引）；`.venv-asr` 及其依赖；`ZHIPU_API_KEY` 三处解析（当前进程 → HKCU 注册表 → `backend/.env`，缺=⚠ 降级不阻塞）；端口占用检测（已占用则询问重启/复用/退出）；前端与语料文件齐全性
  2. 启动：先 ASR 后后端，各自独立窗口；key 通过进程环境注入子进程（不回显）
  3. 健康检查：curl 轮询两端口（≤90s）+ GET 接口抽查
  4. 成功自动打开 http://localhost:8000/ 并打印验收入口清单；失败指向日志窗口
- **改动点清单**：见上
- **风险与限制**：WorkBuddy Python 路径本机特定（换机器设 `YAYA_PYTHON`）；ASR 首次加载模型慢（健康检查放宽 90s）；`ai.py` 只读进程环境变量，`.env` 解析由脚本代劳后注入
