# TASK-0025 全局地图与看板索引化（详情下沉到工具内部文档）

- **项目**：tool_box 全局（跨项目）
- **状态**：已完成
- **优先级**：中
- **创建日期**：2026-11-18
- **完成日期**：2026-11-18

## 原始需求

> 目前每个项目/产品是不是共用一个任务文档和数据地图，项目地图，那些是可以公用的，哪些是需要分开的
> 需要调整
> 只是纯文档变更？那我以后的任务会按之前的文档结构来执行吗
> 可以开始

用户确认现状"全部共用一套地图/看板"，痛点是地图条目长成详情、多项目混排难读；确认按"全局地图只做索引 + 指针，详情下沉到工具内部文档"的方案调整。

## 需求分析

- **目标**：项目地图、数据地图、任务看板从"详情承载"改为"一行索引 + 指针"，并按项目分组；通过 AGENTS.md 和任务模板固化新规则，使以后的任务自动按新结构执行。
- **改动点**（引用项目地图 `docs/project_content.md`）：
  - `docs/project_content.md`、`docs/data_content.md`、`tasks/task_state.md`、`tasks/_TEMPLATE.md`、`AGENTS.md`
- **涉及数据**（引用数据地图 `docs/data_content.md`）：
  - 无数据文件变更（纯文档/规范变更）

## 方案（已确认）

- **实现思路**：全局地图只做索引（每个工具条目 ≤ 2 行），详情下沉到 `tools/<工具名>/` 的 README / docs；数据地图按工具分节；看板加"项目"列；AGENTS.md 加硬性规则；任务模板加"项目"字段。执行顺序"先下沉、后瘦身"，保证零信息丢失。
- **改动点清单**：
  - `docs/project_content.md`：工具索引瘦身 + 新增"地图维护原则"
  - `docs/data_content.md`：登记表按工具分节 + 条目精简
  - `tasks/task_state.md`：两表加"项目"列并回填；归档位置列冗余备注移除
  - `AGENTS.md`：硬性规则新增"全局地图只做索引与指针"
  - `tasks/_TEMPLATE.md`：头部元信息加"项目"字段
- **风险与限制**：信息丢失风险 → 先核对工具内部文档，地图独有信息先补进工具 README/docs 再瘦身；归档备注详情在任务文件中已有，可安全移除；纯文档变更，无代码/数据风险。
- **用户确认日期**：2026-11-18
