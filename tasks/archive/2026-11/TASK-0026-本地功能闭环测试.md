## 需求分析

- **目标**：验证 选股 → 下载 → 解析 → GLM 生成 → 记忆 → 展示 全链路在本地可用，产出通过/失败清单。
- **改动点**（引用项目地图 `docs/project_content.md`）：
  - tools/annual_report_reader/（main.py CLI / server.py Web :5001 / industry.py / fetcher.py / extractor.py / analyzer.py / memory.py）——纯测试，不改代码
- **涉及数据**（引用数据地图 `docs/data_content.md`）：

  - data/output/annual_report_reader/（index.json 状态刷新、companies/ 新报告、pdfs/ 新下载）
- **背景**：index.json 中平安/人寿/中信证券为修复前遗留 error 状态；批量 GLM 生成验收（TASK-0008 遗留）未做。

## 方案（已确认）

- **实现思路**：分四阶段由零成本到真实调用：①环境自检 + `--list`；②记忆与解析闭环（茅台增量跳过 + 平安 error 重跑）；③全链路新下载（五粮液）；④Web server.py 浏览器实测。全程不改代码，发现缺陷单独立任务。
- **改动点清单**：无代码改动；运行产生的数据更新均在 data/output/（不入 git）与 config.json last_run 字段。
- **风险与限制**：依赖 akshare/巨潮外网可用性；GLM 用默认 glm-4-flash（免费档）；运行期间 config.json 的 last_run 会变化。
- **用户确认日期**：2026-11-19

## 发现的缺陷（不在本次修复，另立任务）

- **D1（中）**：平安 2025 年报的「财务表」结构化提取失败（报告显示"自动提取失败，请人工核对年报原文"）；文字带读正常、数字带页码。标准模板公司（茅台/五粮液）提取正常 → 问题限于金融非标模板的表格定位。建议修复：extractor 财务表定位对"财务摘要"章节（平安在第 14-16 页）做回退。
- **D2（低，无功能影响，重跑自愈）**：茅台 index.json 的 `pdf_path` 仍指向 TASK-0012 迁移前的旧缓存路径 `data\cache\...\pdfs\`（该目录已空）。fetcher 只认新路径 `output/pdfs/`（fetcher.py:19），功能不受影响；下次 `--force` 重跑会自动改写。
