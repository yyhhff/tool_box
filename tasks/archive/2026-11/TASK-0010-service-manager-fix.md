## 方案（已确认）

- **实现思路**（针对 4 处已定位 bug）：
  1. 已停止状态下无法重启：`_restart_service` 先调 `_stop_service`，找不到进程时返回 False 直接 return，根本不启动 → 去掉 stop 硬性前置，即便"本就停止"也继续 start。
  2. 停止只认端口：服务假死时端口可能非 LISTEN → 进程定位改为多重兜底（state PID → 脚本路径 → 端口）。
  3. 不留子进程：只杀主进程 → 终止前收集 `children(recursive=True)` 一并处理，再 terminate→超时 kill 主进程。
  4. 状态不同步：进程已消失时 stop 返回失败但 state 仍 running=True → 停止幂等化，进程不存在视为"已停止"成功并清理状态。
  - 启动兜底：端口被占用时识别占用进程是否为本服务进程，是则先清理再启动。
- **改动点清单**：
  - `tools/service_manager/service_manager.py`
  - `tools/service_manager/README.md`（视情况）
  - `docs/lessons.md`（验收通过后沉淀进程管理经验）
- **风险与限制**：
  - Windows 下 `terminate()` 本质是 `TerminateProcess`（强杀），做不到真正优雅退出，平台限制；逻辑上保留 terminate→kill 两级。
  - 按 PID 定位存在极小概率 PID 复用风险，加脚本路径二次校验兜底。
  - 真机验证需实际拉起服务，若依赖（akshare 等）未装可能影响启动验证——区分"逻辑正确"与"环境导致启动失败"。
