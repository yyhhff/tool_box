# 经验库（lessons）

> 记录任务中沉淀的**通用经验**：与具体项目无关、可直接复用到其他项目的做法、坑与技巧。
>
> **收录标准**
> - 只收通用的：换个项目还能用的才写；项目特定细节留在任务归档里
> - 一条经验一句话说清「做什么/避开什么 + 为什么」
> - 条目格式：`- [YYYY-MM-DD]（来源任务）经验内容`（用于其他项目时可省略来源）
> - 同主题经验**合并提炼**进已有条目，不重复堆砌；发现经验过时就改写或删除
>
> **主题分组**：编码与环境 / 爬虫与自动化 / 工作流与协作（可按需新增分组）

## 编码与环境

- [2026-11-16]（TASK-0002）Windows 控制台默认 GBK：print 不要输出 emoji/特殊符号，防 UnicodeEncodeError；文件读写显式 `encoding="utf-8"`；给人看的 CSV 用 `utf-8-sig`，Excel 双击即开不乱码
- [2026-11-16]（TASK-0006）长任务的运行日志要同步落盘（tee 到 run.log）：仅存内存/控制台的日志进程一停就没了，事后无法诊断
- [2026-11-16]（TASK-0007）修复误判类 bug 后要检查所有兜底/降级路径是否又放进了同类误判：主判定用双信号，兜底分支却只看单一弱信号（"或"条件），等于没修——TASK-0006 的"cookie 存在即登录"兜底把双信号修复整个拆穿
- [2026-11-17]（TASK-0010）服务停止要幂等：进程已不存在时按"已停止成功"处理并清理状态，而不是返回失败——否则状态文件残留 running=True，界面卡死；状态查询时也应顺手校正"显示运行中但进程已死"的僵尸状态
- [2026-11-17]（TASK-0010）定位服务进程别只认端口：端口可能未监听（假死）或被 PID 复用；用「记录 PID（脚本路径二次校验）→ 命令行脚本路径 → 端口」三级兜底；停止时连子进程树一起清理（children(recursive=True)），再 terminate→超时 kill
- [2026-11-17]（TASK-0010）重启逻辑别把"先停止成功"当硬前置：服务本就停止时停止会返回失败，导致重启直接中止；应先尽力停止、不检查其返回值，再执行启动
- [2026-11-17]（TASK-0017）Windows + MITM 代理环境下 git 走 HTTPS 报 `CRYPT_E_NO_REVOCATION_CHECK`：`http.schannelCheckRevoke=false` 在此环境无效；根治是改用 openssl 后端并从 Windows 证书库导出系统 CA（Root/CA 存储导出为 PEM）配 `http.sslCAInfo`（写到仓库 local 配置，别改全局）；CA 文件放持久目录如 `~/.git-ca-bundle-wb.pem`，别放 %TEMP%
- [2026-11-17]（TASK-0017）国内连 GitHub：22 端口常被拒，走 SSH over 443（`git@ssh.github.com:owner/repo.git` + `core.sshCommand="ssh -p 443 ..."`）可通；CI/沙箱禁 GUI 弹窗时，HTTPS + 凭据管理器（credential.helper=manager）会卡死，SSH key + BatchMode 非交互才是可自动化方案
- [2026-11-17]（TASK-0018）提供 `.env.example` 模板的项目必须同时忽略真实 `.env`（`.gitignore` 加 `.env` + `.env.*`，再用 `!/.env.example` / `!/path/.env.example` 放行模板）；否则用户填入真实 key 后 `git add .` 直接泄露；用 `git check-ignore -v` 验证"真实 env 被忽略、模板未被忽略"两侧都成立
- [2026-11-17]（TASK-0018）清理"过时"产物前先 grep 全仓引用：看似冗余的历史文件（如 v1 原型 demo.html）常被 README/文档/代码注释当作基线或数据来源引用，直接删会破坏一致性；无引用才可删

## 爬虫与自动化

- [2026-11-16]（TASK-0002）需登录的站点优先用「真实浏览器 + 扫码登录 + storage_state 持久化」，比逆向接口签名（x-s/x-t 类）稳得多，个人小规模抓取首选
- [2026-11-16]（TASK-0002）易变的 CSS 选择器集中到文件顶部常量（如 SEL 字典），页面改版只改一处
- [2026-11-16]（TASK-0002）站内图片/资源直链常需带 Referer 头才能下载
- [2026-11-16]（TASK-0006）反爬规避优先保证指纹一致性：UA 版本与真实浏览器不匹配（如写死 Chrome/130 实际是 159）、navigator.webdriver 标记、无 referer 直达，都比"换不换手机 UA"更容易暴露；桌面浏览器配手机 UA 属于自相矛盾，更易被识别
- [2026-11-16]（TASK-0006/0007）"存在某 cookie"不等于"已登录"：匿名会话也可能被下发同名 cookie（如 web_session）。登录判定：页面用户态（__INITIAL_STATE__ 需逐层反序列化）为主信号；cookie 只认"相对基线新增/变化且 reload 后稳定"的值，reload 复核后再持久化
- [2026-11-16]（TASK-0006）爬虫检测到风控要立即熔断停止，别带病硬跑：空结果连续 N 次、异常连续 N 次即中止，保留已抓内容并给出明确提示——继续请求只会加重风控

## 工作流与协作

- [2026-11-16]（TASK-0003）AI 协作开发采用「方案确认制」：需求分析后先出方案等用户确认再编码，返工率显著降低
- [2026-11-17]（TASK-0008）LLM 带读的 map-reduce 架构：map 阶段要明确要求提取细分要点（分红/回购等），reduce 阶段再汇总；否则 LLM 可能忽略非典型章节（如"重要提示"里的分红预案）
- [2026-11-17]（TASK-0009）服务管理工具设计：通过 `subprocess.Popen` 启动服务，使用 `psutil` 检测端口占用和进程状态；状态持久化到 `data/cache/` 避免重启丢失
- [2026-11-17]（TASK-0009）Web 服务管理界面：Flask 提供 RESTful API（/api/status, /api/start, /api/stop, /api/restart），前端用轮询（每 3 秒）更新状态，避免长轮询占用资源
- [2026-11-17]（TASK-0009）Windows 文件重命名：cmd 中使用 `ren` 而非 `mv`；路径带空格需用引号；重命名后必须同步更新所有引用该路径的文件（如 task_state.md）
- [2026-11-17]（TASK-0009）归档任务命名规范：保持 `TASK-000X-` 前缀不变，文件名用中文描述任务内容，与任务标题保持一致，便于中文搜索和识别
- [2026-11-17]（TASK-0008/0012）年报章节定位别只认"第X节"：保险/券商等金融年报常用「数字编号+标题」或「纯标题独立行」目录；做多模板兼容时让标准格式路径**优先**、命中 ≥3 节即返回，不足再回退通用匹配，避免新逻辑污染标准模板导致回归；用标准章节名白名单约束、目录页（≥3 标题）跳过、页眉重复按规范化名去重
- [2026-11-17]（TASK-0008）PDF 财务表提取容错：表格列可能被拆成多行，用"label 行 + 数字行"块解析，再合并连续数字行；避免扣非/归母串行混淆
- [2026-11-17]（TASK-0008）`--force` 的语义修正：只影响分析逻辑（强制重跑），不应影响已缓存的 PDF 下载（重复下载浪费）
- [2026-11-17]（TASK-0008/0011）Windows 环境变量 key：`setx` 只写注册表、不更新已运行进程；根治做法是在代码读取处加兜底——`os.environ` 读不到时用 `winreg` 从 `HKEY_CURRENT_USER\Environment` 读并回填 `os.environ`（比临时脚本注入可靠，CLI/Web/子进程都覆盖）；读取失败按"未设置"处理，别打印 key 明文
- [2026-11-17]（TASK-0008）Web 进度轮询：后台线程任务需实时更新状态（index.json 或共享变量），前端通过轮询获取进度；避免长时间无响应
