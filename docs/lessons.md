# 经验库（lessons）

> 记录任务中沉淀的**通用经验**：与具体项目无关、可直接复用到其他项目的做法、坑与技巧。
>
> **收录标准**
> - 只收通用的：换个项目还能用的才写；项目特定细节留在任务归档里
> - 一条经验一句话说清「做什么/避开什么 + 为什么」
> - 条目格式：`- [YYYY-MM-DD]（来源任务）经验内容`（用于其他项目时可省略来源）
> - 同主题经验**合并提炼**进已有条目，不重复堆砌；发现经验过时就改写或删除
>
> **主题分组**：编码与环境 / 爬虫与自动化 / 工作流与协作（可按需新增分组）

- [2026-11-20]（TASK-0064）大型单文件「零行为变更」重构用可裁剪的行切片脚本做，别手抄：按顶层声明的精确行区间把 app.py/app.js 原样切进新模块，只改装饰器/加 import/export，函数体一字不动；再用「原版 vs 新版」同时起服务做 A/B 对比证明等价（后端：OpenAPI schema 字节 diff + 22 个 GET 真实 HTTP 响应 0 差异；前端：原单文件静态服 vs 新版同后端，浏览器逐 Tab 点击 + DOM 数组逐字相同），比肉眼 review 几千行可靠得多
- [2026-11-20]（TASK-0064）把单文件脚本拆 ES modules 有两个必踩坑：① 内联 `onclick="fn()"` 依赖 function 天然挂 window，module 作用域不共享，必须在新入口把全部函数显式 `window.fn = fn` 发布，否则按钮全失效；② 被多个模块读写的 `let`（如 audio 文件、当前规则 id）必须连同所有重新赋值的函数放进同一个模块，跨模块 import 是只读绑定不能赋值——生成器要自动校验「模块不得对 import 的名字赋值」，否则运行时报错
- [2026-11-20]（TASK-0064）拆模块生成器必须过滤注释再分析引用：注释里提到某个函数名（如「init 已加载不重复」）会被误判成跨模块引用，生成一条 `import { init } from '../main.js'` 的循环依赖；TDZ 风险只在顶层 const 初始化调用 import 函数时出现，函数体里互调（含大量循环依赖）在 ES module 活绑定下是安全的

## 编码与环境

- [2026-11-16]（TASK-0002）Windows 控制台默认 GBK：print 不要输出 emoji/特殊符号，防 UnicodeEncodeError；文件读写显式 `encoding="utf-8"`；给人看的 CSV 用 `utf-8-sig`，Excel 双击即开不乱码
- [2026-11-16]（TASK-0006）长任务的运行日志要同步落盘（tee 到 run.log）：仅存内存/控制台的日志进程一停就没了，事后无法诊断
- [2026-11-16]（TASK-0007）修复误判类 bug 后要检查所有兜底/降级路径是否又放进了同类误判：主判定用双信号，兜底分支却只看单一弱信号（"或"条件），等于没修——TASK-0006 的"cookie 存在即登录"兜底把双信号修复整个拆穿
- [2026-11-17]（TASK-0010）服务停止要幂等：进程已不存在时按"已停止成功"处理并清理状态，而不是返回失败——否则状态文件残留 running=True，界面卡死；状态查询时也应顺手校正"显示运行中但进程已死"的僵尸状态
- [2026-11-17]（TASK-0010）定位服务进程别只认端口：端口可能未监听（假死）或被 PID 复用；用「记录 PID（脚本路径二次校验）→ 命令行脚本路径 → 端口」三级兜底；停止时连子进程树一起清理（children(recursive=True)），再 terminate→超时 kill
- [2026-11-17]（TASK-0010）重启逻辑别把"先停止成功"当硬前置：服务本就停止时停止会返回失败，导致重启直接中止；应先尽力停止、不检查其返回值，再执行启动
- [2026-11-17]（TASK-0017）Windows + MITM 代理环境下 git 走 HTTPS 报 `CRYPT_E_NO_REVOCATION_CHECK`：`http.schannelCheckRevoke=false` 在此环境无效；根治是改用 openssl 后端并从 Windows 证书库导出系统 CA（Root/CA 存储导出为 PEM）配 `http.sslCAInfo`（写到仓库 local 配置，别改全局）；CA 文件放持久目录如 `~/.git-ca-bundle-wb.pem`，别放 %TEMP%
- [2026-11-17]（TASK-0017）国内连 GitHub：22 端口常被拒，走 SSH over 443（`git@ssh.github.com:owner/repo.git` + `core.sshCommand="ssh -p 443 ..."`）可通；CI/沙箱禁 GUI 弹窗时，HTTPS + 凭据管理器（credential.helper=manager）会卡死，SSH key + BatchMode 非交互才是可自动化方案
- [2026-11-17]（TASK-0018）提供 `.env.example` 模板的项目必须同时忽略真实 `.env`（`.gitignore` 加 `.env` + `.env.*`，再用 `!/.env.example` / `!/path/.env.example` 放行模板）；否则用户填入真实 key 后 `git add .` 直接泄露；用 `git check-ignore -v` 验证"真实 env 被忽略、模板未被忽略"两侧都成立
- [2026-11-17]（TASK-0018）清理"过时"产物前先 grep 全仓引用：看似冗余的历史文件（如 v1 原型 demo.html）常被 README/文档/代码注释当作基线或数据来源引用，直接删会破坏一致性；无引用才可删
- [2026-11-19]（TASK-0020）含中文的 Windows .bat 必须 GBK + CRLF 落盘：LF-only 会让 cmd 解析多字节内容时字节错位直接崩溃；AI 文本工具默认写 UTF-8 也会让中文乱码——改批处理别用 UTF-8 编辑器直改，用原编码读写做精准替换（如 Python `decode('gbk')→replace→encode('gbk')`，每处替换校验命中数），改完跑最小测试桩验证解析
- [2026-11-19]（TASK-0020）同一仓库多个 Web 服务工具的默认端口要错开，且端口必须可配（环境变量）+ 支持自动回退：硬编码 :8000 一旦撞车只能改代码；探测到占用先探健康端点分清"自己人还是别人"——自己人走重启/复用询问，别人自动换备用端口，别一律报错中止
- [2026-11-19]（TASK-0044）"已死但端口未释放"的僵尸服务（netstat 仍 LISTENING，但 tasklist/CIM 查不到、PEB 参数块已空、taskkill 杀不动）别死磕 kill：改用端口自动回退绕开最省事。前提是前端用相对路径（`const API=""`）请求后端——这样换端口零改动；若前端写死端口则换端口会废掉 API。另外 uvicorn `reload=True` 会 spawn 子进程，kill 父进程时子进程残留正是僵尸来源，常驻服务应设 `reload=False`。判定"占用者是不是自己人"用健康端点返回内容（面板=text/html，旧版=JSON），比命令行关键字匹配可靠（僵尸根本查不到命令行）
- [2026-11-20]（TASK-0056）接管第三方客户端的本地缓存做"数据迁移"前，必须先确认那份缓存是不是权威数据源：Electron 客户端常把本地 JSON 只当 seed（本例 `wb:sidebar:seed` + `stale:true`），启动后用云端列表覆盖（bundle 里直接写着 `logCacheAuthoritativeOverwrote`）。若服务端接口不支持改归属（本例 `updateConversation` 只收 title/visibility/status/extraInfo/expertId/locale），本地写入就无法持久可见——此时应"诚实降级"：保留本地能力 + 事后只读校验 + 明确提示，而不是继续叠加补丁或伪造云端数据
- [2026-11-20]（TASK-0052）"先探测端口再启动服务"既有 TOCTOU 竞态，又逼调用方靠共享环境变量猜端口；同机多个工具共用默认段时会互相抢、自动打开错页面。根治是让服务自己 `bind`+`listen`，成功后把真实端口写进事实文件（含 service/pid/url），清理脚本和浏览器 helper 只读该文件；浏览器 helper 必须用 `/health` 的 service 标识握手，**校验失败宁可不开**，stale 注册表同样拒绝；同机工具各用专属端口段，清理按注册表 pid + 命令行特征识别自己人并排除其他服务特征，不靠端口猜归属。扩充清理识别范围时要反查同机其他服务的启动命令——只按 `server.py` 这类通用文件名匹配会误杀别家的 ASR 子服务，排除规则必须覆盖主服务与所有子服务标识
- [2026-11-20]（TASK-0060）SQLite 测试造数据时，外层连接 `UPDATE` 未提交就调用内部会另开连接写同库的函数（如 `update_user_activity`）→ 报 `database is locked`：写操作必须串行化，每次先 `commit()` 再调内部函数；测试改动完要按原值逐字段恢复（xp/streak/成就表等），尤其注意"读页面"触发的懒计算端点（如 achievements）会偷偷写库加 XP，验收后须连它一起清理

- [2026-11-19]（TASK-0037）接管第三方客户端的私有数据（SQLite + 侧边栏快照）前：先只读摸清按什么隔离（user_id / 目录）、UI 直接渲染哪份文件、DB 是否 WAL；写入必须「停客户端→备份 db+wal+shm→原子替换→重启」，且用 dry-run 只读预演验证计划；能只读验证的部分（解析/去重/幂等/串号隔离）用临时目录单测全覆盖，真机写操作留给用户验收
- [2026-11-20]（TASK-0066）后台进程逐条写共享 JSON（读全量→改一条→写回全量）时，主进程并行改同一文件会被后台的旧快照覆盖（审批状态/审计标记凭空回退）：要么等后台结束再改，要么让两边共用同一进程，别「你写一条我改一条」——事后统一重算一次即可恢复，且入库按主键去重的幂等设计保证不会重复
- [2026-11-20]（TASK-0066）Windows 下 Python `Path.write_text()` 默认把 `\n` 转成 `\r\n`，若原文件是 LF，一次写入就产生全文件 diff、还会和多车道并行改动大面积冲突：追加/重写已有文本文件必须 `open(..., newline="\n")` 显式锁定换行符；序列化 JSON 想要「顶层缩进 + 数组元素单行」的既有风格，用哨兵占位序列化再替换回紧凑串，别手写括号解析。用户配置的 `core.autocrlf` 只影响 git checkout/add，不影响 Python 写盘
- [2026-11-20]（TASK-0066）LLM 生成长结构化 JSON（约 1800+ tokens）时超时/解析失败的根因常是 max_tokens 过低导致尾部 `]}` 被截断：先提 max_tokens 到实测长度之上，再留一个「按括号栈补齐尾部闭合符」的确定性修复兜底（只补闭合、不改内容），失败率可从 ~35% 降到接近 0；同类的「body 行数与 lines 不一致」则用结构化字段（lines）反向重建文本字段（body）消除，而非反复重生成

## 爬虫与自动化

- [2026-11-16]（TASK-0002）需登录的站点优先用「真实浏览器 + 扫码登录 + storage_state 持久化」，比逆向接口签名（x-s/x-t 类）稳得多，个人小规模抓取首选
- [2026-11-16]（TASK-0002）易变的 CSS 选择器集中到文件顶部常量（如 SEL 字典），页面改版只改一处
- [2026-11-16]（TASK-0002）站内图片/资源直链常需带 Referer 头才能下载
- [2026-11-16]（TASK-0006）反爬规避优先保证指纹一致性：UA 版本与真实浏览器不匹配（如写死 Chrome/130 实际是 159）、navigator.webdriver 标记、无 referer 直达，都比"换不换手机 UA"更容易暴露；桌面浏览器配手机 UA 属于自相矛盾，更易被识别
- [2026-11-16]（TASK-0006/0007）"存在某 cookie"不等于"已登录"：匿名会话也可能被下发同名 cookie（如 web_session）。登录判定：页面用户态（__INITIAL_STATE__ 需逐层反序列化）为主信号；cookie 只认"相对基线新增/变化且 reload 后稳定"的值，reload 复核后再持久化
- [2026-11-16]（TASK-0006）爬虫检测到风控要立即熔断停止，别带病硬跑：空结果连续 N 次、异常连续 N 次即中止，保留已抓内容并给出明确提示——继续请求只会加重风控
- [2026-11-20]（TASK-0065）agent-browser 在本环境每次 Bash 调用结束守护进程即被回收：跨命令用 `snapshot -i` 拿到的 ref 到下一步必失效（"Unknown ref"），且新命令里页面常变空页。解法是把「打开→交互→断言」整条链塞进**单条命令的一次 `eval(async JS)`** 里完成，用稳定 CSS 选择器/`window.fn()` 而非 ref；不要在多个 Bash 调用间维持浏览器状态
