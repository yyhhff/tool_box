# 夜班自动化 NightOps 使用说明

> **定位**：每晚 23:00–09:00 窗口内每 30 分钟自动醒来一次，无人值守地迭代你的项目（修复 bug、补测试、改文档、补功能）。
> **触发方式**：ZCode Cron 自动化（`0,30 23,0-8 * * *`），**错过任何一次下次醒来自动接手**，无需人工干预。
> **当前状态**：已演练验证（TASK-0028），今晚 23:00 首跑。

## 1. 快速开始

### 1.1 前置条件

- **电脑整夜不睡眠**：ZCode Desktop 必须保持运行（系统电源设置里把"睡眠"改为"从不"）
- **git 可用**：本机原生 git 不可用时自动走 WSL git（Ubuntu-22.04，已配置作者身份 `yyhhff <2273508857@qq.com>`，可 `git config --global --unset user.name/user.email` 撤销）

## 2. 工作原理

### 2.1 醒来模型（关键）

NightOps 不是"23:00 启动一次整晚运行"，而是**窗口内每 30 分钟一醒的波次制**：

| 触发时间 | 语义 |
|---------|------|
| 23:00 | 首醒：今晚夜报不存在，先巡库刷新任务池 |
| 23:30 | 续跑：直接按优先级领任务，不重复巡库 |
| 00:00 | 续跑 |
| ... | ... |
| 08:30 | 末醒：若当前时间 ≥ 09:00，本轮做全晚总收口 |

**好处**：
- 错过 23:00（关机/ZCode 未运行）→ 下次醒来（如 23:30）自动接手，不浪费整晚
- 每轮只做 1-2 个任务，上下文压力小，不易崩溃
- 任何一轮中断，30 分钟后下一轮自动恢复

### 2.2 父子 agent 分工

每轮醒来后，父 agent（夜班总指挥）按以下顺序派发子 agent：

| 角色 | 类型 | 职责 |
|------|------|------|
| 侦察员 | Explore（只读） | 定位 bug 根因、影响面、改动点清单；产出结论不产出文件 |
| 实现者 | general-purpose | 按角色提示词（后端/前端/内容）实现变更 |
| 测试员 | general-purpose | 跑测试 + 对照验收标准逐条核对，给出 PASS/FAIL 及证据 |

**子 agent 提示词必带四条**：
1. 禁止调用 AskUserQuestion（无人应答）
2. 禁止早停（交付物不完整不得结束）
3. 错误按章程第 5 节协议：先分析→假设清单→每假设一次验证→3 假设失败标 blocked 换下一任务
4. 遵守章程第 2 节红线（项目文档即白名单、credentials/GLM 计费/真机爬虫等）

## 3. 核心特性

### 3.1 白名单：项目文档即授权边界

NightOps 只做**文档中你已写明的设计目标**：

| 来源 | 夜间可做 |
|------|----------|
| `tools/<工具>/README.md` 及其 `docs/`（架构契约、章程、路线图） | 文档写明的目标、"下一项"、待办方向 |
| `tasks/active/TASK-*.md` | 该任务的需求与验收标准范围内的实现、缺陷修复 |
| `docs/project_content.md` 工具索引中的"状态"列 | 状态注记的遗留事项（如"待前端开发"） |
| 测试失败 / 运行报错 | 修复至绿（天然授权） |

**范围外**（文档没有、用户没说过的新方向、接口/数据口径变更、商业模式类决策）→ 夜间只写提案文件到 `tasks/active/`（命名 `TASK-XXXX-<短名>-proposal.md`），**不实施**。

### 3.2 红线（任何任务、任何理由都不得触碰）

1. 不读取、不修改、不提交 `tools/workbuddy-multi-account/credentials/` 下任何文件（含登录态 token）
2. 不运行会产生 **GLM/ZHIPU API 真实计费** 的批量生成任务（单元测试一律 mock；annual_report_reader 的真实生成只做单次冒烟且 ≤3 篇）
3. xhs_crawler **不真机抓取**（风控风险）：只跑 mock/单元测试与本地 Web 界面静态检查
4. `data/output/`、`data/cache/` 不提交 git；不改 `.gitignore`；不提交任何 `.env`、密钥、凭据文件
5. 不 force push、不 rebase 已推送历史、不删除他人文件；删除/覆盖任何文件前必须先读其内容确认
6. 章程本身、`AGENTS.md`、`docs/git_guide.md` 不可修改
7. 端口被占按各工具既有回退逻辑处理，不杀非本项目的进程

### 3.3 错误协议（有错先分析，禁机械重试）

1. **先分析后动手**：报错必须先读完整错误输出 + 相关代码，形成 ≥1 个**书面假设**（写进任务文件变更记录），禁止看一眼报错就改
2. **一假设一验证**：每个假设只做一次针对性修复并验证；修复必须伴随对假设的印证或证伪结论
3. **三假设封顶**：连续 3 个假设失败 → 标 `blocked`（记录：报错原文、已试假设、当前最佳猜测、建议），**换下一任务**
4. **禁止机械重试**：同一命令不带新输入原样重跑 = 违规；超时/网络类错误最多重试 1 次且必须先确认非必现
5. 单任务 blocked 不影响整体循环：继续领取下一任务直到收口时间

### 3.4 危险操作即跳过（用户指示）

凡需用户确认的危险操作（批量删除/覆盖非本任务文件、修改系统或全局环境配置、pip 全局安装、git push / force / rebase、真实计费 API 批量调用等）：

- 不执行、不询问、不硬试
- 该任务标 `blocked`（原因注明"危险操作待用户确认"），**换下一任务继续**
- 夜报中汇总列出，晨起由你裁定

### 3.5 方案选择自主决策（用户指示）

章程第 2 节授权范围内的方案选择（技术选型、实现路径、文件组织、修复方向等）：

- 由总指挥分析后**自行选定**
- 在任务文件"方案（已确认）"节记录备选项与取舍理由
- 不得因"多种方案待选"而 blocked、等待或询问

### 4.1 夜报（tasks/night_reports/YYYY-MM-DD.md）

每晚每轮醒来都会追加"## 醒来 HH:MM"进展段，最后一次醒来做全晚总收口。结构：

```markdown
# 夜报 YYYY-MM-DD
## 预检
<第 0 节结果，逐条>
## 醒来 23:00
- 完成项：项目 | 变更摘要 | 提交 | 测试结论
- blocked 项：项目 | 卡点 | 已试假设 | 建议
## 醒来 23:30
...
## 醒来 09:00（全晚总收口）
- 完成项汇总（N）
- blocked 项汇总（M）
- 提案项（K）
- 看板与归档
- 次日建议
- 配额消耗概况
```

**晨起必读**：查看完成项、blocked 项（是否需你决策）、次日建议。

## 5. 常见问题

### 5.1 错过 23:00 会怎样？

- **不会整晚缺席**：下次醒来（如 23:30）会自动接手，按"续跑"模式直接领任务
- **首启判定**：今晚夜报不存在/任务池未刷新 → 先巡库刷新任务池再干活

### 5.2 并行会话在同一个仓库工作怎么办？

- **精确暂存**：`git add` 只加本任务明确文件路径，禁止 `git add -A/.`
- **编号占坑**：任务文件创建后立即提交占号，撞号立即顺延（编号以 git 提交时刻为准）
- **不代提他人**：工作区有他人未提交变更，不回滚、不覆盖、不代提，只在夜报中记录

### 5.3 git 在 cmd PATH 中不可用怎么办？

- 夜班自动走 **WSL git**（Ubuntu-22.04，已配置作者身份 `yyhhff <2273508857@qq.com>`）
- 使用方式：`wsl bash -c "git -C /mnt/d/code/tool_box ..."`
- 可用 WSL 命令检查：`wsl bash -c "git --version"` / `wsl bash -c "git -C /mnt/d/code/tool_box status"`

### 5.4 如何关闭/重启夜班自动化？

- **关闭**：`CronDelete -id automation-b76f9ced-bf0c-41c1-9281-bef2f5c2557c`
- **重启**：`CronUpdate -id automation-b76f9ced-bf0c-41c1-9281-bef2f5c2557c -enabled true`

### 5.5 如何手动触发一轮夜班（非 23:00 窗口）？

- 说"触发夜班"或"演练夜班"，会按 23:00 窗口模式运行一轮（提交会被允许，普通夜班只 commit 不 push）

### 5.6 如何撤销 git 身份配置？

```bash
wsl bash -c "git config --global --unset user.name && git config --global --unset user.email"
```
